# CLAUDE.md Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a repo-root `CLAUDE.md` that gives coding agents three standing instructions: brainstorm before building any new feature, verify changes in the running app via the Chrome DevTools MCP before committing, and walk the user through the diff with the `hunk-review` skill before committing any code.

**Architecture:** A single new Markdown file at the repo root. No code changes — Claude Code (and compatible agents) load `CLAUDE.md` automatically at session start, so no wiring is needed beyond the file's existence and content.

**Tech Stack:** Markdown only.

**Spec:** [GitHub issue #16](https://github.com/mnatanbrito/invest-buddy/issues/16) — the issue body covers instructions 1 and 2 below; instruction 3 (hunk-review walkthrough before committing) was added afterward by direct user request in conversation, not tracked in the issue. No separate design doc was written for either (per the issue's own point 1, brainstorming is what decides whether a spec is warranted, and for a three-instruction file it isn't).

## Global Constraints

- File must live at the repo root: `CLAUDE.md`.
- Keep it concise and imperative — it is loaded into every agent session.
- Scope is exactly the three instructions below. Do not add convention links (testing/migrations/PR flow) — the issue explicitly defers those to a follow-up.
- Instruction 1 (verbatim intent): always invoke the `superpowers:brainstorming` skill when working on any new feature, to determine whether a written spec is needed before implementation begins.
- Instruction 2 (verbatim intent): use the Chrome DevTools MCP to test new features and bug fixes in the running app before committing the code.
- Instruction 3 (verbatim intent): always walk the user through the changes using the `hunk-review` skill before committing any code.

- [ ] **Step 1: Write the file**

Create `CLAUDE.md` at the repo root with this content:

```markdown
# CLAUDE.md

Instructions for coding agents working in this repository.

## Before starting any new feature

Invoke the `superpowers:brainstorming` skill before writing any code for a
new feature. Use it to decide whether the feature needs a written spec
before implementation begins.

## Before committing

Use the Chrome DevTools MCP to run the feature or bug fix in the app and
confirm it behaves as expected before committing the change.

Always walk the user through the changes using the `hunk-review` skill
before committing any code.
```
